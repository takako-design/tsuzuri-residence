# TSUZURI RESIDENCE 神戸御影
## Codex 実装・ブラッシュアップ指示 v1.0

既存のNext.jsプロジェクトを確認し、現在のトップページを土台としてブラッシュアップしてください。
ゼロから別サイトを作り直さず、既存コンポーネント、コピー、画像、デザイントークンを再利用してください。

## 0. 作業開始前

1. リポジトリ全体を確認する
2. package.json、tsconfig.json、Next.js設定、Tailwind設定、public/images、app、components、libを確認する
3. 現在の実装構造、使用中の依存関係、未使用コード、欠落アセットを整理する
4. 作業前に変更計画を短く提示する
5. 可能なら作業用ブランチを作成する

## 1. 最終デザイン方針

- B案「Artful Editorial」70%
- A案「Architectural Quiet Luxury」25%
- C案「Botanical Grandeur」5%
- コンセプト：Quiet Grandeur｜大きく、静かに、美しく。
- 大きな表現、スタイリッシュさ、見やすさ、上品さを両立する
- 一般的な介護施設サイトではなく、高級レジデンス、建築誌、ラグジュアリーホテルのブランドサイトとして見せる
- Claude Designの参考画像はレイアウト、写真比率、余白、タイポグラフィの参考として使用する
- Claude Design固有のHTMLや独自要素はコピーせず、既存のNext.js、TypeScript、Tailwind CSSへ再実装する

## 2. 維持するもの

- セクション順
- 掲載コピー
- Warm White、Residence Ivory、Deep Charcoal、Botanical Green、Champagne Bronzeを中心とした配色
- Shippori Mincho、Noto Sans JP、Cormorant Garamond
- 現在の画像トーン
- 医療・看護の表現ルール
- アクセシビリティ方針
- Hero、Dining、Families、Final CTAの基本方向

## 3. 全体修正

- PCの最大コンテンツ幅は1280〜1440px
- 主要セクションの上下余白は120〜160px
- スマートフォンは72〜96px
- Hero以外にもResidence、Dining、Appで大きな表現を作る
- 写真の面積と大小差を増やす
- 均等カードの連続を避ける
- 同じレイアウトの繰り返しを避け、スクロールのリズムを作る
- 1画面内の主役を1つに絞る
- 小さく、細く、薄い文字で高級感を作らない

## 4. タイポグラフィ

- Hero見出し：PC 64〜88px、SP 40〜52px
- セクション見出し：PC 44〜64px、SP 32〜42px
- 本文：PC 16〜18px、SP 16px以上
- 補足：14px以上
- 行間：本文1.75前後、見出し1.35〜1.45
- Bronzeを本文や重要情報の文字色に使用しない
- 薄いグレーを重要情報に使用しない
- clamp()と既存CSS変数を使い、無秩序にハードコードしない

## 5. Hero

- 現在の全面写真と左寄せコピーを維持
- 100svh、PCで最低760px程度
- 見出しを一段大きくする
- 左側のグラデーションを強化し、文字コントラストを安定させる
- ヘッダーは初期透明、スクロール後Warm White
- CTAは「見学を予約する」「資料を取り寄せる」の2つ
- Hero直下の信頼情報を読みやすくする
- 巨大な装飾英字は追加しない

## 6. Concept

- 中央配置と大きな余白を維持
- 見出しを拡大する
- 本文幅を640〜720px
- 3つの価値はカード化せず、番号、罫線、余白で整理する
- 背景英字は使用しても極薄く限定的にする

## 7. Residence

最重要の修正対象。

- 建築誌のような非対称エディトリアルレイアウト
- メイン写真を50〜60vw程度まで拡大
- コピーを写真に少し重ねる
- ラウンジ、居室、庭の写真を均等サイズにしない
- 画像の角丸と影を強くしすぎない
- 小さな説明カードを減らし、写真、見出し、短いコピーで見せる
- スマートフォンでは負のmargin依存を避け、CSS Gridで安全に再構成する

## 8. Dining

- Botanical Green背景を維持
- 季節の和御膳を主役として大きく見せる
- ダイニング空間写真と料理写真に大小差を付ける
- 3特徴はカードではなく罫線と余白で整理
- 季節表現や花は一点だけ
- 旅館、和食店、季節限定サイトに見せない
- 「食事選択のデモを見る」を明確なCTAにする

## 9. Medical & Wellness

- A案の明瞭な情報設計を基準
- 健康相談スペースの写真1枚を大きめに配置
- 情報は2列または4列
- 装飾英字や花は使わない
- 看護職員24時間常駐と、協力医療機関による定期往診・緊急時連携を明確に区別する
- 医師常駐、医師24時間対応と誤認させない

## 10. Digital Concierge App

- スマートフォン型ではなく大型タブレットを主役にする
- 食事選択画面をメインにする
- 必要ならホーム画面を背面に1枚だけ重ねる
- HPの料理写真とアプリ内の料理写真を一致させる
- 機能説明は4つ以内
- 巨大な装飾文字は使わない
- CTA「アプリデモを操作する」を明確にする

## 11. Families

- 現在の大きな写真と左右分割を維持
- 写真を一回り大きくする
- 正面顔ではなく、会話、手元、後ろ姿、食卓を中心にする
- 情報項目を3つ以内に整理
- 本人同意とプライバシー尊重を明確にする

## 12. Information / FAQ

- 料金の大きな数字を維持
- 補足文字を小さくしすぎない
- 入居フローはPC横、SP縦
- 仮の地図表現を上品な簡易マップ、または写真＋アクセス情報へ変更する
- FAQの操作領域を44px以上にする
- 質問と回答の階層を明確にする

## 13. Final CTA / Footer

- 全面背景写真と中央寄せを維持
- 見出しを44〜60pxへ拡大
- 背景グラデーションを調整
- Footer本文・リンクは14〜16pxを基本
- 架空プロジェクト注記を読めるサイズで表示

## 14. スマートフォン

- PCの縮小版にしない
- Headerはロゴ＋メニュー
- 複数カラムは1カラムへ再設計
- ResidenceはCSS Gridで大小差を作る
- Dining写真は画面幅いっぱい
- Appはタブレットが画面幅内に収まること
- 下部に資料請求／見学予約の固定CTA
- 320px、375px、390pxで横スクロールなし
- 操作対象44px以上
- 固定CTAでFooterを隠さない

## 15. コード品質

- TypeScriptのbuild errorを無視しない
- next.config.mjsの `typescript.ignoreBuildErrors: true` を削除し、型エラーを修正する
- 画像最適化が可能なら `images.unoptimized: true` を削除する
- semantic HTMLを維持
- altを確認
- `:focus-visible`を確認
- `prefers-reduced-motion`へ対応
- Hero画像以外は遅延読み込み
- responsive sizesを適正化
- 画像領域を確保してCLSを防ぐ
- 未使用コンポーネント、重複CSS、不要依存を整理する
- 参照している画像ファイルがpublic/imagesに存在するか確認する
- ダミーリンクやクリック不能ボタンを残さない

## 16. 検証

以下を実行し、失敗した場合は修正する。

```bash
pnpm install
pnpm lint
pnpm build
```

利用可能ならPlaywrightまたはブラウザ確認で以下を確認する。

- PC 1440px
- Tablet 768px
- Mobile 390px
- Mobile 375px
- Mobile 320px
- 横スクロールなし
- メニュー開閉
- 固定CTA
- FAQ
- アンカーリンク
- フォーカス表示
- reduced motion
